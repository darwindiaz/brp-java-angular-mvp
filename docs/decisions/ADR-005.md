# ADR 005 Aprovisionamiento del administrador inicial

**Estado:** implementado en el incremento de identidad. **Requisitos:** RS-01 y RS-05.

**Contexto.** Liquibase 5.0.4 registra y valida un checksum por changeset.
El hash BCrypt inicial difiere entre instalaciones y no debe entrar al
changelog ni aparecer en mensajes de error.

**Alternativas.** Insertar un hash fijo, sustituir un parámetro dentro de SQL
o ejecutar una tarea Java sin parámetros de changelog. Un hash fijo acopla
las instalaciones. Una sustitución introduce el secreto en el procesamiento
del changelog y su comportamiento de checksum depende del tipo de cambio.

**Decisión.** El changeset 005 usa un `CustomTaskChange` sin parámetros
dinámicos. Se comprobó en el JAR 5.0.4 que el wrapper calcula el checksum
por serialización en ausencia de un proveedor de checksum personalizado.
El hash se lee exclusivamente al ejecutar la tarea y se asigna a un
parámetro JDBC. Una única sentencia inserta usuario, módulo y evento de
sistema en la transacción de Liquibase.

**Consecuencias.** El primer arranque exige un hash BCrypt válido. Un fallo
revierte el aprovisionamiento. Los reinicios sobre una base ya migrada no
aplican otra vez el changeset. Para modificar el comportamiento de
aprovisionamiento después de publicarlo, añadir un changeset con otro ID.
El hash se suministra fuera de Git y los logs de SQL y parámetros deben
permanecer fuera de los niveles de traza.
